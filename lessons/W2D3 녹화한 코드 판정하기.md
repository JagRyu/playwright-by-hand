# W2D3: 녹화한 코드 판정하기

> **손으로 짜는 Playwright** · W2 첫 테스트 · 8/40회
> 형식: 워밍업 5분 → 개념 10분 → 예측 퀴즈 → 손으로 치기 30분 → 설명하기 10분 → 기록 5분
> 오늘은 **코드를 내가 쓰지 않고 녹화로 만든다.** 그리고 그 코드를 판정한다. AI 가 짠 테스트를 판정하려고 이 공부를 시작했는데, 오늘이 그 첫 연습이다.

## 워밍업 (5분)

**1. `fn(obj)` 옮기기** (어제 다음 액션)

`w2-first-test/my-test.js` 의 `myTest` 안에서 `fn(obj);` 줄을 `시작` 을 찍는 줄 **위로** 옮긴다.

```js
function myTest(name, fn) {
  const obj = { page: '새 브라우저 탭', browserName: 'chromium' };
  fn(obj);
  console.log(`[${name}] 시작: 탭을 만든다`);
  console.log(`[${name}] 끝: 탭을 닫는다`);
}
```

첫 번째 `myTest('로그인', ...)` 의 출력 3줄을 예측하고, `node my-test.js` 로 확인한 뒤 **원래대로 되돌린다.**

내 예측: 
내 함수 안: 새 브라우저 탭
[로그인] 시작: 탭을 만든다
[로그인] 끝: 탭을 닫는다

실제:
내 함수 안: 새 브라우저 탭
[로그인] 시작: 탭을 만든다
[로그인] 끝: 탭을 닫는다

**2. 주인 찾기** (어제 배운점 3) `page.getByRole('button', { name: 'Login' })` 이 돌려주는 것은 무엇인가? 그래서 그 뒤에 `.click()` 을 붙일 수 있는 이유는?

내 답: getByRole('button', { name: 'Login'}) 을 돌려준다. Locator를 돌려주기에 행위를 행하는 .click()을 붙일 수 있는 것이다.

## 개념 (10분)

### codegen: 클릭하면 코드가 써진다

```
npx playwright codegen https://www.saucedemo.com
```

브라우저와 작은 창(Inspector)이 같이 뜬다. 브라우저에서 클릭하고 입력하면 Inspector 에 코드가 **한 줄씩 써진다.** 다 했으면 브라우저 창을 닫으면 끝난다.

만들어지는 코드도 `test('test', async ({ page }) => { ... })` 모양이다. 어제 본 "`test` 에 함수를 넘기는" 그 구조를 codegen 도 그대로 쓴다.

### 찾는 방법 네 번째: `page.locator('[data-test="..."]')`

codegen 은 saucedemo 에서 이렇게 찾는다.

```js
page.locator('[data-test="username"]')
```

| 부분 | 뜻 |
|---|---|
| `page.locator(...)` | 괄호 안의 **CSS 선택자**로 찾는 쪽지를 만든다. 이것도 `page` 의 메서드이고 Locator 를 돌려준다 |
| `[data-test="username"]` | 화면 코드에서 `data-test` 이름표가 `username` 인 요소 |

`data-test` 는 **개발자가 테스트하라고 붙여 둔 이름표**다. 화면 글자가 바뀌어도 이름표는 그대로라서 잘 안 깨진다. (회사에서 개발자에게 "테스트용 이름표 붙여 주세요"라고 부탁할 수 있는 이유다)

> 브라우저에서 F12 → 입력칸 우클릭 "검사" 를 하면 `data-test="username"` 이 실제로 보인다.

### 녹화는 "한 일"만 적는다

codegen 은 내가 **한 동작**을 받아 적는다. 내가 눈으로 확인한 것은 받아 적지 않는다. 이게 무엇을 뜻하는지는 퀴즈와 과제에서 직접 본다.

## 예측 퀴즈 (실행하기 전에 답을 적는다)

> 예측 칸은 실행 뒤에도 고치지 않는다. 틀렸으면 아래에 `실제:` 를 따로 적는다.

**Q1.** 로그인 → 장바구니 담기 → 장바구니 열기를 녹화하면, codegen 이 만든 코드에 `expect` 는 몇 줄 있을까?

내 예측: 3줄
실제: 0줄

**Q2.** 로그인 뒤 상품 목록 화면에서 아래 줄을 실행하면 어떻게 될까? (힌트: 상품 목록 화면에 `Add to cart` 버튼이 몇 개 있나?)

```js
await page.getByRole('button', { name: 'Add to cart' }).click();
```

내 예측: 화면에 'Add to cart' 버튼이 6개나 있어 어떤 버튼을 클릭할지 판단하지 못했다는 Error 메시지를 출력할 것이다.
실졔: Error: locator.click: Error: strict mode violation: getByRole('button', { name: 'Add to cart' }) resolved to 6 elements

**Q3.** codegen 은 `fill` 앞에 `click` 을 한 줄 더 적는다. 그 `click` 줄을 지우면 어떻게 될까? (힌트: 내가 쓴 `login.spec.js` 를 보라)

내 예측: fill 앞에 click 을 사용한다는건 입력필드를 클릭하여 문자를 입력 가능한 상태를 만들기 위함인데, click 을 지운다면 실제로 입력은 안될 것이고 fill 에 실패했다고 Error 가 표출될 것이다.
실제: click 줄을 지워도 입력됨.

## 손으로 치기 (30분)

### 과제 1. 녹화하기

1. `w2-first-test` 폴더에서 `npx playwright codegen https://www.saucedemo.com` 을 친다.
2. 뜬 브라우저에서 순서대로 한다.
   - `standard_user` / `secret_sauce` 로 로그인
   - `Sauce Labs Backpack` 의 `Add to cart` 클릭
   - 오른쪽 위 장바구니 아이콘 클릭
3. Inspector 의 **Copy** 버튼으로 코드를 복사해 `w2-first-test/codegen-raw.spec.js` 에 붙인다. **한 글자도 고치지 않는다.**
4. 브라우저 창을 닫고 `npx playwright test codegen-raw` 로 돌린다. (파일 이름 일부만 써도 그 파일만 돈다)

결과(passed/failed): passed

### 과제 2. 판정하기

`codegen-raw.spec.js` 를 읽고 표를 채운다. 내 `login.spec.js` 와 나란히 놓고 본다.

| 질문 | 내 답 |
|---|---|
| `expect` 가 있나? 몇 줄인가? | 0 |
| 지워도 동작이 같은 줄이 있나? 어느 줄인가? | username, password click 하는 줄이 없어도 될 것 같다. |
| 내 코드와 **찾는 방법**이 다른 곳은? | codegen 으로 작성된 곳은 다 locator 로 작성되어 있다. |
| 이 코드가 통과하면, 무엇이 맞다는 것이 증명되나? | expect 가 없어서 증명되지 않는다. |

### 과제 3. 확인을 넣어 다시 쓰기 (새 파일)

`w2-first-test/cart.spec.js` 를 **손으로** 쓴다. 테스트 이름은 `장바구니 담기`.

- 로그인은 내 방식(`getByPlaceholder`, `getByRole`)으로 쓴다.
- `Add to cart` 버튼과 장바구니 아이콘은 codegen 이 찾은 `page.locator('[data-test="..."]')` 를 빌려 쓴다.
- 마지막에 **확인 두 줄**을 넣는다.
  - 장바구니 화면으로 왔다: `toHaveURL` (주소에 무엇이 들어가는지는 브라우저 주소창을 보고 정한다)
  - 담은 상품이 보인다: `getByText(...)` + `toBeVisible()`

다 쓰면 `npx playwright test` 로 전체를 돌린다.

결과(몇 passed): 5 passed (2.5s)

### 과제 4. 고장 내기 (예측 → 실행 → 되돌리기)

1. `codegen-raw.spec.js` 의 비밀번호를 `'wrong'` 으로 바꾼다.
   - 내 예측: (실패하나? 몇 초 뒤에? **몇 번째 줄**에서? 메시지는?) -> 10줄에서 5초 뒤에 data-test="add-to-cart-sauce-labs-backpack"을 찾지 못했다는 Error 가 발생할 것이다.
   - 실제 결과: (`Error:` 로 시작하는 줄 · 실패한 줄 번호 · 걸린 시간) -> 10줄에서 30000ms 후에 Error: locator.click: Test timeout of 30000ms exceeded. Call log:- waiting for locator('[data-test="add-to-cart-sauce-labs-backpack"]') -> expect 는 최대 기다림이 5000ms, .click(), .fill() 은 테스트 전체 제한 시간 30000ms까지
2. `cart.spec.js` 의 `Add to cart` 줄을 `page.getByRole('button', { name: 'Add to cart' })` 로 바꾼다 (Q2 확인).
   - 내 예측: 동일한 이름의 버튼이 6개 있다는 Error 가 나온다.
   - 실제 결과: (`Error:` 줄과 `resolved to ? elements` 의 숫자) -> Error: locator.click: Error: strict mode violation: getByRole('button', { name: 'Add to cart' }) resolved to 6 elements

## 설명하기 (10분)

공식: ① 무엇인가 ② 왜 ③ 내가 본 증거. 물음표 없이 단정한다.

1. codegen 이 만든 코드는 통과해도 "테스트"라고 부르기 어렵다. 왜인가? (과제 2 판정표와 과제 4-1 실패 메시지를 증거로) -> codegen이 만든 코드는 내가 한 동작(클릭·입력)만 적고, 확인(expect)은 하나도 적지 않는다. 테스트는 기대 결과가 맞는지 판정해야 하는데, 이 코드는 동작이 끝까지 실행되기만 하면 통과한다. 그래서 장바구니에 상품이 실제로 담겼는지는 증명하지 못한다.
2. 과제 4-2 의 에러는 왜 **좋은** 에러인가? 손으로 테스트할 때 동료에게 "Add to cart 눌러 주세요" 라고 말하는 상황과 비교해서 쓴다. -> 동료에게 "Add to cart 눌러 주세요"라고만 하면 동료는 6개 중 하나를 골라 누르고, 나는 무엇이 눌렸는지 모른 채 결과를 믿게 된다. Playwright는 짐작해서 누르는 대신 "정확히 어느 것인지 말하라"고 멈춰 세운다. 그래서 엉뚱한 상품을 담고도 통과하는 일이 생기지 않는다.
