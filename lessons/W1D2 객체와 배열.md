## 개념 (10분)

### 객체: 이름표 붙은 값 묶음

```js
const tc = {
  id: 'TC-001',
  title: '로그인 성공',
  passed: true,
};

console.log(tc.id);        // 'TC-001'   ← 점(.)으로 꺼낸다
console.log(tc.priority);  // undefined  ← 없는 이름표를 꺼내면 에러가 아니라 undefined
tc.passed = false;         // 안의 값은 바꿀 수 있다
```

Playwright 의 `{ page }` 도 객체와 관련이 있다. 오늘 배운 것으로 W1D3 에서 푼다.

### 배열: 순서 있는 값 목록

```js
const roles = ['admin', 'user', 'guest'];

console.log(roles[0]);       // 'admin'   ← 번호(인덱스)는 0부터
console.log(roles.length);   // 3
console.log(roles[5]);       // undefined ← 없는 번호도 에러가 아니라 undefined
```

### 객체가 든 배열: 테스트 결과표

```js
const results = [
  { id: 'TC-001', passed: true },
  { id: 'TC-002', passed: false },
  { id: 'TC-003', passed: true },
];

console.log(results[1].id);   // 'TC-002'
```

엑셀 표와 같다. 배열 한 칸 = 한 행, 객체의 이름표 = 열 이름.

### 배열에서 골라내기: `filter` 와 `find`

```js
const failed = results.filter((r) => r.passed === false);
// [{ id: 'TC-002', passed: false }]   ← 조건에 맞는 것 "전부"를 배열로

const tc3 = results.find((r) => r.id === 'TC-003');
// { id: 'TC-003', passed: true }      ← 조건에 맞는 "첫 번째 하나"
```

`(r) => r.passed === false` 는 W1D1 의 화살표 함수다. **`filter` 에 함수를 통째로 넘기면, `filter` 가 배열의 칸마다 그 함수를 실행해 본다.** `test('로그인', async ({ page }) => {...})` 에서 `test` 에 함수를 넘기는 것과 같은 구조다.

### `throw`: 이상한 값이면 그 자리에서 멈추기 (W1D1 에서 미룬 것)

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error('b는 0일 수 없습니다');   // 함수가 여기서 멈추고 빨간 에러가 난다
  }
  return a / b;
}
```

`return '특별한 값'` 은 조용히 넘어가고, `throw` 는 바로 드러난다.

### 과제 2. 테스트 결과표 다루기

아래 결과표를 그대로 친다.

```js
const results = [
  { id: 'TC-001', title: '로그인 성공', passed: true },
  { id: 'TC-002', title: '잠긴 계정 로그인', passed: true },
  { id: 'TC-003', title: '빈 비밀번호', passed: false },
  { id: 'TC-004', title: '상품 정렬', passed: true },
  { id: 'TC-005', title: '장바구니 담기', passed: false },
];
```

| 할 일 | 목표 출력 |
|---|---|
| ① 실패한 TC 만 골라내기 (`filter`) | TC-003, TC-005 두 개가 든 배열 |
| ② `'TC-004'` 찾기 (`find`) | TC-004 객체 하나 |
| ③ 통과한 개수 세기 | `3` |
| ④ W1D1 의 `passRate` 를 이 파일에 복사해서 통과율 구하기 | `60.0%` |

- 힌트 ③: 통과한 것만 `filter` 한 배열의 `length`
- ④에서 함수를 복사해 오는 게 번거로울 것이다. 그 불편함을 기억해 둔다. W1D3 에서 해결한다.

### 과제 3. `passRate` 이상 입력 막기 (W1D1 에서 미룬 것)

1. 어떤 입력을 "이상하다"고 볼지 정한다. (음수? `passed > total`? 그 외?)
2. 이상한 입력에 **특별한 값을 돌려줄지, `throw` 할지** 고르고 이유를 한 줄 적는다.
   - 이유:
3. `0/0` 은 `'0.0%'` 로 둘지 바꿀지 정한다. ("하나도 안 돌린 것"과 "전부 실패"가 구분되는가?)
   - 결정과 이유:
4. `throw` 를 골랐다면, 이상한 입력을 넣어 빨간 에러가 나는 것을 확인한다. 그 뒤 그 줄은 주석 처리한다. (에러가 나면 아래가 실행되지 않으니까)

### (선택) `map`: 칸마다 바꿔서 새 배열 만들기

```js
const ids = results.map((r) => r.id);   // ['TC-001', 'TC-002', ...]
```

`results` 를 W1D1 의 `formatResult` 로 바꿔서 `['TC-001: PASS', ...]` 배열을 만들어 본다.

## 설명하기 (10분)

1. `const user` 의 `role` 을 바꿀 수 있었던 이유는? `user = {}` 는 왜 안 되나? -> `user`라는 상자(변수)가 `const`이고, 안의 `role`은 `const`가 아니라서 바꿀 수 있다. `user = {}`는 `const`인 `user` 자체에 다시 대입하는 것이라 안 된다.
2. `filter` 와 `find` 는 무엇이 다른가? 조건에 맞는 게 하나도 없으면 각각 무엇을 돌려줄까? (예측 후 실행해서 확인) -> `filter`는 for문처럼 반복하며 조건에 맞는 것을 모두 찾아내고, `find`는 조건에 맞는 첫 번째 객체 하나를 돌려준다. 하나도 없으면 `filter`는 빈 배열(`length`는 0)을, `find`는 `undefined`를 돌려준다.
3. `results.filter((r) => r.passed === false)` 를 한 조각씩 내 말로 읽는다. -> `results` 배열에서 `passed`가 `false`인 객체를 모두 골라 새 배열을 만든다.
4. 과제 3 에서 `throw` 와 특별한 값 중 무엇을 골랐고 왜인가? -> 처음에는 `throw` 쓰는 법을 몰라서 아는 문법인 `else if`를 썼다. 그런데 `else if`로 안내 문구를 돌려주면 나중에 결과서 시트에 '개수는 음수일 수 없습니다.' 같은 문구가 찍힐 것 같아서, `throw` 쓰는 법을 물어보고 바꿨다.
