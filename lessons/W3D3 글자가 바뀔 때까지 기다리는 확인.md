# W3D3: 글자가 바뀔 때까지 기다리는 확인

> **손으로 짜는 Playwright** · W3 기다림과 확인 · 13/40회
> 형식: ❓ 답 5분 → 워밍업 5분 → 개념 10분 → 예측 퀴즈 → 손으로 치기 30분 → 설명하기 5분 → 기록 5분
> 오늘 새로 쓰는 것: `textContent()`(나쁜 예로), `toHaveText()`. 지금까지는 글자가 **생기는지**를 봤다. 오늘은 이미 있는 글자가 `Ready` → `Saving...` → `Saved` 로 **바뀌는** 화면을 확인한다.

## W3D2 ❓ 답 (5분, 읽기만)

**`click()`, `toBeVisible()` 처럼 괄호를 쓰는 메서드에 어떤 옵션을 넣을 수 있나?**

외우지 않는다. **VS Code 가 알려 준다.**

| 하는 법 | 보이는 것 |
|---|---|
| 괄호 안에 `{ }` 를 치고 그 사이에 커서를 둔 채 `Ctrl + Space` | 넣을 수 있는 옵션 이름 목록 |
| 메서드 이름 위에 마우스를 올린다 | 그 메서드 설명과 옵션 설명 |

지금까지 쓴 옵션을 모으면 이렇다.

| 메서드 | 옵션 | 뜻 |
|---|---|---|
| `getByRole('button', { ... })` | `name`, `exact` | 버튼 이름, 정확히 같은지 |
| `getByText('글자', { ... })` | `exact` | 정확히 같은지 |
| `toBeVisible({ ... })` | `timeout` | 이 확인만 몇 ms 까지 기다릴지 |
| `click({ ... })` | `timeout` | 이 클릭만 몇 ms 까지 기다릴지 |

`timeout` 은 기다리는 메서드라면 거의 다 받는다. 오늘 과제 1 에서 `Ctrl + Space` 를 직접 눌러 본다.

## 워밍업 (5분, 배운 것 복습)

**1.** `Saved` 가 2초 뒤에 보이는 화면이다. 아래 줄은 몇 초쯤 걸리고 끝날까? (W3D2 개념 2)

```js
await expect(page.getByText('Saved')).toBeVisible({ timeout: 10000 });
```

- 통과/실패: 통과
- 걸린 시간(2초쯤 / 10초쯤 중): 2초

**2.** AI 가 7초 걸리는 `Slow Save` 앞에 아래처럼 썼다. W3D2 에서 배운 모양으로 **두 줄을 한 줄로** 고쳐 쓴다.

```js
await page.waitForTimeout(7000);
expect(await page.getByText('Saved').isVisible()).toBe(true);
```

고친 줄: expect(await page.getByText('Saved').isVisible({timeout: 7000})).toBe(true);
정답: await expect(page.getByText('Saved')).toBeVisible({ timeout: 10000 });

**3.** W3D2 과제 1 에서 `getByRole('button', { name: 'Save' })` 가 실패한 이유를 한 줄로 쓴다. (`resolved to ? elements`)

내 답: resolved to 2 elements

## 개념 (10분)

### 1. 오늘 쓸 연습 페이지

```js
const html = `
<button onclick="document.getElementById('status').textContent = 'Saving...'; setTimeout(() => document.getElementById('status').textContent = 'Saved', 2000)">Save</button>
<p id="status" data-test="status">Ready</p>
`;
```

| 부분 | 뜻 |
|---|---|
| `<p id="status" data-test="status">Ready</p>` | 처음 글자가 `Ready` 인 줄. `id` 는 페이지 안에서 부르는 이름이고, `data-test` 는 Playwright 가 `getByTestId('status')` 로 찾는 이름표다 (W2D4 config 의 `testIdAttribute: 'data-test'`) |
| `document.getElementById('status')` | 페이지 안에서 `id` 가 `status` 인 요소를 찾는다 |
| `.textContent = 'Saving...'` | 그 요소의 글자를 `Saving...` 으로 **바꾼다** |
| 가운데 `;` | 앞의 일을 하고 이어서 뒤의 일을 한다 |
| `setTimeout(() => ... = 'Saved', 2000)` | 2초 뒤에 글자를 `Saved` 로 바꾼다 (W3D1 ❓ 답과 같은 모양) |

정리하면 `Save` 를 누르는 순간 `Saving...`, 2초 뒤에 `Saved` 로 바뀐다.

```
클릭 전: Ready  ──클릭──▶  Saving...  ──2초──▶  Saved
```

### 2. 글자 확인에도 두 종류가 있다

W3D1 의 `isVisible()` / `toBeVisible()` 와 똑같은 짝이다.

| | 한 번 읽는 확인 | 기다리는 확인 |
|---|---|---|
| 모양 | `expect(await 쪽지.textContent()).toBe('Saved')` | `await expect(쪽지).toHaveText('Saved')` |
| 하는 일 | **지금** 글자를 한 번 읽어 와서 비교한다 | 글자가 `Saved` 가 될 때까지 **5초 동안 계속 다시 읽는다** |
| W3D1 의 짝 | `isVisible()` + `toBe(true)` | `toBeVisible()` |

`textContent` 라는 이름이 두 번 나온다. 헷갈리지 않게 구분한다.

- 개념 1 의 `.textContent = '...'` 는 **페이지 안에서** 글자를 바꾼다.
- 오늘 Playwright 코드의 `쪽지.textContent()` 는 **테스트에서** 그 글자를 읽어 온다. 괄호가 붙고, `await` 가 필요하다.

### 3. `toHaveText` 는 글자 **전체**를 본다

| | 찾기 `getByText('Save')` | 확인 `toHaveText('Save')` |
|---|---|---|
| 기본 | 글자 **일부**만 맞아도 찾는다 (W3D1) | 글자 **전체**가 같아야 통과한다 |

찾기와 확인은 기본이 반대다. (일부만 확인하는 `toContainText` 도 있다. 오늘은 쓰지 않는다)

**Q1.** `Save` 를 누르고 바로 `expect(await page.getByTestId('status').textContent()).toBe('Saved')` 를 하면? (확인은 **과제 2**)

- 통과/실패: 실패

- 통과/실패: 실패

## 손으로 치기 (30분)

`w3-wait` 폴더에서 한다. 새 파일은 `status.spec.js` 다.

### 과제 1. 클릭 전 글자 확인

1. `status.spec.js` 를 만들고 `import` 줄과 개념 1 의 `html` 을 넣는다.
2. 테스트를 하나 쓴다.

| 테스트 이름 | 하는 일 | 마지막 확인 |
|---|---|---|
| `상태 - 클릭 전` | `setContent(html)` (클릭은 하지 않는다) | `await expect(page.getByTestId('status')).toHaveText('Ready')` |

3. 마지막 줄의 `toHaveText('Ready')` 를 잠깐 `toHaveText('Ready', { })` 로 바꾸고, `{ }` 사이에 커서를 둔 채 `Ctrl + Space` 를 누른다.
   - 목록에 보인 이름 3개: ignoreCase, signal, timeout, useInnerText
   - (목록이 안 뜨면 비워 두고 채점 때 알려 준다)
4. `, { }` 를 지워 원래대로 되돌린다.
5. `npx playwright test status` → 결과를 적는다.
   - 결과(몇 passed · 걸린 시간): 1 passed / 1.2s

### 과제 2. 한 번 읽는 확인 (Q1 확인)

`상태 - 클릭 전` **아래에** 테스트를 하나 더 쓴다.

| 테스트 이름 | 하는 일 | 마지막 확인 |
|---|---|---|
| `상태 - 저장 후` | `setContent(html)` → `Save` 클릭 | `expect(await page.getByTestId('status').textContent()).toBe('Saved')` |

1. `npx playwright test status` → 결과를 적는다.
   - 실제 결과: (몇 passed · 몇 failed · `Expected:`·`Received:` 줄 · `상태 - 저장 후` 의 걸린 시간)
     - 1 passed 1 failed
       - Expected: "Saved" / Received: "Saving..."
       - 152ms
2. 실패한 줄을 지우지 말고 **앞에 `//` 를 붙여 주석으로 남긴다.** 그 아래에 `await expect(page.getByTestId('status')).toHaveText('Saved');` 를 쓰고 다시 돌린다.
   - 결과(몇 passed · `상태 - 저장 후` 의 걸린 시간):
     - 2 passed
     - 2.5s

### 과제 3. 고장 내기 (예측 → 실행 → 되돌리기)

모두 `상태 - 저장 후` 테스트에서 한다.

1. `toHaveText('Saved')` 를 `toHaveText('Save')` 로 바꾸고 `npx playwright test -g "저장 후"` 로 돌린다 (Q2 확인).
   - 실제 결과: (`Expected:`·`Received:` 줄 · `Timeout:` 줄 · 걸린 시간)
     - Expected: "Save" / Received: "Saved" / Timeout: 5000ms / 5.2s
   - `Call log` 에서 `unexpected value` 로 나온 값 두 개:
     - unexpected value "Saving..."
     - unexpected value "Saved"
2. `'Saved'` 로 되돌린다. 이번에는 `html` 의 `2000` 을 `7000` 으로 바꾸고 같은 명령으로 돌린다 (Q3 확인).
   - 실제 결과: (`Expected:`·`Received:` 줄 · `Timeout:` 줄 · 걸린 시간)
     - Expected: "Saved" / Received: "Saving..." / Timeout:  5000ms / 5.2s
3. W3D2 에서 배운 대로 `toHaveText('Saved')` 에 `{ timeout: 10000 }` 을 넣고 다시 돌린다.
   - 결과(통과/실패 · 걸린 시간):
     -  통과 / '상태 - 저장 후' 자체는 7.6s test 는 8.6s
4. `7000` 을 `2000` 으로, `{ timeout: 10000 }` 은 지워서 되돌린다. `npx playwright test` 로 **전체가 통과하는지** 확인한다. (`wait`·`timeout`·`status` 세 파일이 같이 돈다)
   - 결과(몇 passed): 7 passed

## 설명하기 (5분)

공식: ① 무엇인가 ② 왜 ③ 내가 본 증거. 물음표 없이 단정한다. **증거는 `실제 결과:` 칸의 숫자나 메시지를 그대로 옮긴다.**

1. AI 가 `expect(await page.getByTestId('status').textContent()).toBe('Saved')` 로 확인을 썼다. 통과시킬 것인가, 고칠 것인가? 고친다면 무엇으로? (증거: 과제 2 의 `Received:` 값과 두 번의 걸린 시간) -> 고친다. 'Saved' 가 표출되기까지의 설정 시간이 2초로 toBe(..) 사용 시 Expected: "Saved" / Received: "Saving..." 으로 차이가 발생하여 실패한다. toHaveText(..)를 사용하여 대기한 후 확인할 수 있도록 한다.

2. `getByText('Save')` 는 `Saved` 를 찾는데, `toHaveText('Save')` 는 `Saved` 에서 실패한다. 왜인가? (증거: 과제 3-1 의 `Received:` 값) -> getByText는 'Save'가 포함하기만 하면 찾고, toHaveText는 정확히 일치하는 값을 찾고자 하기 때문이다. 실제로 toHaveTest('Save')로 작성하면 Expected: "Save" / Received: "Saved" 이라는 Error 결과가 표출되는 것을 확인했다.
