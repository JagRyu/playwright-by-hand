## 개념 (10분)

### 화살표 함수의 네 가지 모양

네 줄은 **모두 같은 일**을 한다. 행 하나를 받아서 `id` 를 돌려준다.

| # | 모양 | 코드 |
|---|---|---|
| ① | 함수 선언 | `function getId(r) { return r.id; }` |
| ② | 화살표 + `{ }` | `const getId = (r) => { return r.id; };` |
| ③ | 화살표 한 줄 | `const getId = (r) => r.id;` |
| ④ | 화살표 + 구조 분해 | `const getId = ({ id }) => id;` |

읽는 요령:

- **`=>` 왼쪽 = 받는 것, 오른쪽 = 돌려주는 것.** `(r) => r.id` 는 "r 을 받아서 r.id 를 돌려준다".
- `=>` 오른쪽에 `{ }` 가 있으면 ②처럼 **`return` 을 직접 써야** 돌려준다. (W1D1 에서 막힌 곳)
- 왼쪽이 `({ id })` 면 받은 객체에서 `id` 만 꺼낸 것이다. (W1D3)
- 읽기 어려우면 **①로 펼쳐서** 읽는다.

### 메서드 안에 들어간 화살표

```js
results.map(({ id }) => id)
```

`map` 에 ④를 이름 없이 바로 넣은 것이다. `map` 이 행마다 이 함수를 불러서, 돌려받은 값으로 새 배열을 만든다.

### 오늘 새로 쓰는 것 하나: `join`

배열을 **한 문자열로 이어 붙인다.** 괄호 안에 사이에 넣을 글자를 준다.

```js
['TC-003', 'TC-005'].join(', ')   // 'TC-003, TC-005'
['a', 'b'].join('\n')             // 줄바꿈으로 이어 붙임 → a 다음 줄에 b
```

## 예측 퀴즈 (실행하기 전에 답을 적는다)

> 예측 칸은 실행 뒤에도 고치지 않는다. 틀렸으면 아래에 `실제:` 를 따로 적는다.

**Q1.** 무엇이 출력될까?

```js
const double = (n) => n * 2;
console.log([1, 2, 3].map(double));
```

내 예측: 2, 4, 6

**Q2.** Q1 과 무엇이 다른가? 무엇이 출력될까?

```js
console.log([1, 2, 3].map((n) => { n * 2 }));
```

내 예측: double 함수를 따로 선언하지 않고, 한줄로 풀어서 넣은 것 같다. 2, 4, 6
실제: [undefined, undefined, undefined]

**Q3.** 무엇이 출력될까?

```js
const ids = results.filter(({ passed }) => !passed).map(({ id }) => id);
console.log(ids);
```

(`!passed` 는 "passed 가 아니면", 즉 `passed === false` 와 같다)

내 예측: TC-003, TC-005

## 설명하기 (10분)

1. 표의 ②에서 `return` 을 지우면 무엇이 돌아오나? Q2 와 같은 이유로 설명한다. -> undefined가 돌아온다. '=>' 뒤에 '{ }'가 있으면 함수 몸통이라서 return 을 써야만 값을 돌려주는데, return 이 없으면 undefined 를 돌려준다. getId2(results[0]) 가 undefined 를 찍었고, Q2 도 [ undefined, undefined, undefined ] 가 나왔다.
2. 아래 Playwright 코드를 한 조각씩 내 말로 읽는다. 모르는 함수 이름(`fill`, `toHaveURL`)은 이름으로 짐작해도 된다. -> @playwright/test 파일에서 test, expect 함수를 빌려온다. '로그인 성공' 테스트 열고, 브라우저 탭(page)를 이용한다. 'https://www.saucedemo.com' 주소로 이동하여 화면이 열릴 때까지 기다린다. 'Username' 이라는 Placeholder 입력필드를 찾을 때까지 기다렸다가 'standard_user'을 입력한다. 'Password' 라는 Placeholder 입력필드를 찾을 때까지 기다렸다가 'secret_sauce' 를 입력한다. 'Login' 이라는 버튼을 찾을 때까지 기다린 후 클릭한다. page의 URL에 '/inventory/' 사이의 글자 'inventory' 글자가 보이면 성공.
   ```js
   import { test, expect } from '@playwright/test';

   test('로그인 성공', async ({ page }) => {
     await page.goto('https://www.saucedemo.com');
     await page.getByPlaceholder('Username').fill('standard_user');
     await page.getByPlaceholder('Password').fill('secret_sauce');
     await page.getByRole('button', { name: 'Login' }).click();
     await expect(page).toHaveURL(/inventory/);
   });
   ```

## 기록 (5분)

`w1-js-basics/NOTES.md` 에 W1D5 칸을 추가하고, 맨 아래에 **W1 회고**를 세 줄 쓴다.

- W1 에서 가장 많이 늘었다고 느끼는 것:  설치해서 익숙하게만 쓰던 `import`, `export`, `await`, `test()`, `expect()`, `goto()`가 각각 어떤 원리로 불러와지고 동작하는지 이해했다. 변수·함수·배열·객체와 `map`, `filter`, `find`도 손으로 쳐 보며 익혔다. 이제 간단한 Playwright 테스트 코드를 보면 무엇을 하려는 코드인지 읽을 수 있다.
- 아직 제일 불안한 것: 화살표 함수와 구조 분해가 아직 낯설다. 한 줄로 이어 쓸지, 변수나 함수로 나눠 담을지도 아직 스스로 판단하지 못한다.
- W2 에 바라는 것: 잘 짜인 Playwright 코드를 읽고 따라 치면서, 왜 그렇게 짰는지 이해하고 싶다.
