# W2D2: 화면에서 찾고 확인하기

> **손으로 짜는 Playwright** · W2 첫 테스트 · 7/40회
> 형식: 워밍업 10분 → 개념 10분 → 예측 퀴즈 → 손으로 치기 25분 → 설명하기 10분 → 기록 5분
> 오늘 새로 쓰는 것: `getByText`, `toBeVisible`. 어제는 "URL 이 바뀌었나"만 봤다. 오늘은 **화면에 글자가 떴나**를 확인하고, 실패하는 로그인도 테스트한다.

## 워밍업 (10분): `test` 흉내 내기 (W2D1 ❓)

어제 남긴 질문: "`test` 가 탭을 만들어 객체에 담아 내 함수에 넣어 준다"가 와닿지 않는다.
`test` 가 하는 일을 JS 로 흉내 낸 코드를 직접 돌려 본다.

**0. 어제 빈칸 먼저.** W2D1 수업 파일의 워밍업 답(`page.url()` 의 모양)과 Q1 `실제:` 줄을 채운다.

**1.** `w2-first-test/my-test.js` 를 만들고 아래를 친다. (이름이 `.spec.js` 가 아니라서 Playwright 테스트가 아니다. `node` 로 돌린다)

```js
function myTest(name, fn) {
  console.log(`[${name}] 시작: 탭을 만든다`);
  const obj = { page: '새 브라우저 탭', browserName: 'chromium' };   // ① 객체를 만든다
  fn(obj);                                                          // ② 내 함수를 부르면서 그 객체를 넣는다
  console.log(`[${name}] 끝: 탭을 닫는다`);
}

myTest('로그인', ({ page }) => {          // ③ 나는 객체에서 page 를 꺼내 쓴다
  console.log('내 함수 안:', page);
});

myTest('없는 이름', ({ loginPage }) => {
  console.log('내 함수 안:', loginPage);
});
```

**2. 실행 전에 예측한다.** 출력 6줄을 순서대로 적는다.

내 예측: 로그인 시작: 탭을 만든다 / 내 함수 안: { page: '새 브라우저 탭', browserName: 'chromium' } / 로그인 끝: 탭을 닫는다 / Error

**3.** `node my-test.js` 로 돌리고 비교한다.

실제: 
[로그인] 시작: 탭을 만든다
내 함수 안: 새 브라우저 탭
[로그인] 끝: 탭을 닫는다
[없는 이름] 시작: 탭을 만든다
내 함수 안: undefined
[없는 이름] 끝: 탭을 닫는다

**4.** 진짜 `test` 와 다른 점 하나: 마지막 `{ loginPage }` 가 진짜 Playwright 에서는 무엇이 나왔나? (W2D1 과제 2-2)

내 답: undefined 가 아닌 Error 를 뱉었다.

## 개념 (10분)

### 찾기와 하기는 다르다

```js
await page.getByPlaceholder('Username').fill('standard_user');
//         └──────── 찾기 ────────────┘ └─── 하기 ────┘
```

| 부분 | 하는 일 | `await` |
|---|---|---|
| `page.getByPlaceholder('Username')` | **어떻게 찾을지** 적은 쪽지를 만든다 (locator) | 필요 없다. 바로 끝난다 |
| `.fill(...)`, `.click()` | 그 쪽지로 화면에서 찾아서 **동작**한다 | 필요하다. 오래 걸린다 |
| `expect(...).toBeVisible()` | 그 쪽지로 찾아서 **확인**한다 | 필요하다. 최대 5초 기다린다 |

`await` 를 `.fill()` 앞이 아니라 줄 맨 앞에 쓰는 건, 줄 전체가 끝날 때까지 기다리라는 뜻이다. (W1D4 ❓ "await 를 줄마다 붙여도 되나"의 답: 동작과 확인 줄에는 **전부** 붙이는 게 맞다)

### 찾는 방법 세 가지

| 찾는 방법 | 무엇으로 찾나 | 예 |
|---|---|---|
| `getByPlaceholder('Username')` | 입력칸 안의 회색 안내 글자 | 아이디·비밀번호 칸 |
| `getByRole('button', { name: 'Login' })` | 역할(버튼, 링크…)과 이름 | 로그인 버튼 |
| `getByText('Products')` | 화면에 보이는 글자 | 제목, 에러 문구 |

`getByText` 는 **글자 일부만 맞아도** 찾는다. `/inventory/` 가 URL 일부만 봤던 것과 같다.

### 확인 하나 더: `toBeVisible`

```js
await expect(page.getByText('Products')).toBeVisible();   // 'Products' 글자가 화면에 보이나?
```

`toHaveURL` 처럼 **최대 5초 동안 다시 확인**하다가, 보이는 순간 통과한다.

## 설명하기 (10분)

공식: ① 무엇인가 ② 왜 ③ 내가 본 증거. 물음표 없이 단정한다.

1. 워밍업의 `myTest` 를 보고, 진짜 `test` 가 `page` 를 어떻게 내 함수에 넣어 주는지 설명한다. -> `test` 는 내 함수를 매개변수로 들고 있다가, 브라우저 탭으로 `{ page, browserName, ... }` 객체를 만든 뒤 `fn(객체)` 처럼 `({ page }) => { ... }` 를 불러 그 객체를 넣어 준다. 그래서 `import` 하지 않은 `page` 를 내 함수 안에서 `{ page }` 로 꺼내 쓸 수 있다. `my-test.js` 에서 `myTest` 가 `fn(obj)` 로 내 함수를 부르자 `[로그인] 시작` 과 `끝` 사이에 `내 함수 안: 새 브라우저 탭` 이 찍혔다.
2. `page.getByText('Products')` 앞에는 `await` 가 없어도 되는데, `expect(...).toBeVisible()` 앞에는 왜 필요한가? (Q1 결과를 증거로) -> `page.getByText('Products')` 는 화면을 찾지 않고 "어떻게 찾을지"를 적은 쪽지(locator)만 바로 만들기 때문에 기다릴 것이 없다. `expect(...).toBeVisible()` 은 받은 쪽지로 화면에서 글자를 찾아 최대 5초 동안 확인하는 일이라, 끝날 때까지 `await` 로 기다려야 한다. Q1 에서 `console.log(page.getByPlaceholder('Username'))` 는 기다림 없이 `getByPlaceholder('Username')` 쪽지를 그대로 출력했다. 과제 2 에서 `.click()` 을 빠뜨리고 `page.getByRole('button', { name: 'Login' })` 까지만 쓴 줄은 쪽지만 만들고 에러 없이 지나가서 버튼이 눌리지 않았다.
3. 과제 3-1 에서 오타를 냈을 때 테스트는 무엇을 알려 줬나? 손으로 테스트할 때와 비교해서 쓴다. -> 오타를 낸 테스트는 터미널에서 무엇을 찾다가(`getByText(...)` 에 오타가 그대로 보임), 왜(`element(s) not found`), 얼마나 기다리고(`Timeout: 5000ms`), 몇 번째 줄에서 실패했는지 알려 줬다. 손으로 테스트할 때는 빨간 상자가 뜬 것만 보고 넘어가기 쉽지만(실제로 VL For Shore 에서 `Gas Turbine` 의 `e` 가 빠진 `Gas Turbin` 을 못 보고 넘어간 적이 있다), Playwright 테스트는 글자 하나만 달라도 실패로 잡는다. 다만 이번 실패는 제품이 아니라 내가 작성한 테스트 코드의 오타 때문에 발생했다. 테스트가 실패했다고 해서 곧 제품 결함인 것은 아니므로, 제품 결함인지 테스트 코드가 틀린 것인지는 메시지를 보고 내가 판단해야 한다.
