## 설치 (10분)

VS Code 터미널에서 `playwright-by-hand` 폴더에 있는지 확인하고, 한 줄씩 친다.

```
mkdir w2-first-test
cd w2-first-test
npm init -y
npm pkg set type=module
npm i -D @playwright/test
npx playwright install chromium
```

| 줄 | 하는 일 |
|---|---|
| `npm init -y` | 이 폴더용 `package.json` 을 만든다 |
| `npm pkg set type=module` | W1D3 에서 손으로 넣은 `"type": "module"` 을 명령으로 넣는다 (`import` 쓰려고) |
| `npm i -D @playwright/test` | Playwright 를 이 폴더에 설치한다. `node_modules` 폴더가 생긴다 |
| `npx playwright install chromium` | 테스트가 띄울 크롬 브라우저를 내려받는다 |

확인: `npx playwright --version` 을 치면 `Version 1.65.0` 같은 줄이 나온다.

> `node_modules` 는 `.gitignore` 에 이미 들어 있어서 커밋되지 않는다. 지우고 싶으면 지워도 `npm i` 로 다시 생긴다.

## 개념 (5분)

### 테스트 파일 = `.spec.js`

Playwright 는 이름이 **`.spec.js` 로 끝나는 파일**을 테스트 파일로 찾는다. 오늘 만들 파일은 `login.spec.js` 다.

### 실행 = `npx playwright test`

```
npx playwright test            # 브라우저를 화면에 안 띄우고 돌린다 (빠름)
npx playwright test --headed   # 브라우저가 화면에 뜬다
```

### `page` 는 어디서 오나 (W1D3 ❓ 마무리)

W1D3 에서 `map` 이 행을 하나씩 꺼내서 내 화살표 함수에 넣어 줬다.

```js
results.map(({ id }) => id)      // map 이 행을 넣어 준다
```

`test` 도 똑같다. `test` 가 **브라우저를 열고 새 탭(`page`)을 만들어서** 내 함수에 넣어 부른다. 내 함수가 끝나면 탭을 닫는다.

```js
test('로그인 성공', async ({ page }) => { ... })   // test 가 page 를 넣어 준다
```

그래서 `import` 한 건 `test`, `expect` 둘뿐인데 `page` 를 쓸 수 있다. **오늘 `--headed` 로 돌리면서 브라우저가 뜨는 순간이 "`test` 가 `page` 를 만드는 순간"이다.**

## 예측 퀴즈 (실행하기 전에 답을 적는다)

> 예측 칸은 실행 뒤에도 고치지 않는다. 틀렸으면 아래에 `실제:` 를 따로 적는다.

**Q1.** 아래 줄은 무엇을 찍을까? (W1D2 에서 `typeof` 를 썼다)

```js
console.log(typeof test, typeof expect);
```

내 예측: function, function

**Q2.** `async ({ page }) =>` 를 `async (tools) =>` 로 바꾸고, 안에서 `tools.page.goto(...)` 로 쓰면 어떻게 될까? (W1D3 에서 "Playwright 는 구조 분해만 받는다"고 했다. 진짜인지 확인한다)

내 예측: 객체의 Key 가 'page' 로 정의되어 있기 때문에 Error 발생한다.

**Q3.** 비밀번호를 `'wrong'` 으로 바꾸면 마지막 줄 `expect(page).toHaveURL(/inventory/)` 은 **바로** 실패할까, **조금 기다렸다가** 실패할까?

내 예측: await로 되어 있기때문에 기다렸다가 실패할것이다.

### 과제 1. 첫 테스트 돌리기

1. W1D5 설명하기 2번의 로그인 테스트를 친다.
2. `import` 바로 아래에 Q1 의 `console.log` 를 넣는다.
3. `click()` 줄 바로 아래에 `console.log(page.url());` 를 넣는다.
4. `npx playwright test` 로 돌린다. 마지막에 `1 passed` 가 나오면 성공이다.
5. `npx playwright test --headed` 로 한 번 더 돌린다. 브라우저가 뜨는지 본다. (1초도 안 걸려서 깜빡하고 지나간다)

> `typeof` 줄이 **두 번** 찍혀도 정상이다. Playwright 가 파일을 두 번 읽기 때문이다(목록을 만들 때 한 번, 실행할 때 한 번).

### 과제 2. 고장 내기 (각각 예측 → 실행 → 원래대로 되돌리기)

**고장 낸 것을 되돌린 뒤에 다음 고장을 낸다.** 망가진 테스트 파일이 하나라도 있으면 그 폴더의 테스트가 **전부** 안 돈다.

1. `async ({ page }) =>` → `async (tools) =>`, 안의 `page.` 를 전부 `tools.page.` 로 (Q2 확인)
   - 내 예측: Error
   - 실제 결과: First argument must use the object destructuring pattern
2. `async ({ page }) =>` → `async ({ loginPage }) =>`, 안의 `page.` 를 전부 `loginPage.` 로 (예전 For Ship 에서 해 봤던 그것)
   - 내 예측: Error
   - 실제 결과: Test has unknown parameter "loginPage".
3. 비밀번호 `'secret_sauce'` → `'wrong'` (Q3 확인). 실패 메시지에서 `Expected` 와 `Received` 두 줄을 찾아 옮겨 적는다.
   - 내 예측: ?
   - 실제 결과 (Expected / Received): Expected pattern: /inventory/
    Received string: "https://www.saucedemo.com/"

```
npx playwright test --debug
```

## 설명하기 (10분)

공식: ① 무엇인가 ② 왜 ③ 내가 본 증거. 물음표 없이 단정한다.

1. `import` 한 적 없는 `page` 를 쓸 수 있는 이유를 설명한다. -> `page` 는 `import` 한 것이 아니라, `test` 가 테스트를 실행할 때 새 브라우저 탭을 만들어 객체에 담아 내 함수에 넣어 준 것이다. 나는 그 객체에서 `{ page }` 로 꺼내 쓴다. `--headed` 로 돌리자 테스트가 시작될 때 브라우저가 떴다.
2. 과제 2-2 에서 `{ loginPage }` 가 에러 난 이유를 설명한다. -> Playwright 가 정해 둔 객체의 key 이름(예: `page`) 이외에는 사용하지 못하도록 막기 때문에 에러가 발생한다. `{ loginPage }` 로 바꾸자 `Test has unknown parameter "loginPage".` 가 나왔다. 
3. 과제 2-3 에서 실패가 바로 나왔나, 기다렸다가 나왔나? 그 결과를 보고 `expect` 가 무엇을 하는지 짐작해서 쓴다. (정답은 W3 에서 다룬다. 짐작이어도 단정해서 쓴다) -> 실패는 바로 나오지 않고 5초를 기다린 뒤에 나왔다. `expect` 는 한 번 보고 결과를 정하지 않고, 최대 5초 동안 현재 URL 에 `inventory` 가 들어 있는지 반복해서 확인한다. 들어오는 순간 바로 통과하고, 5초가 지나도 안 들어오면 실패한다. 실패 메시지에 `Timeout: 5000ms` 와 `Call log` 의 `14 ×`(14번 확인)가 찍혔고, 성공한 테스트는 1초도 걸리지 않았다. 그래서 서버 응답이 느려도 5초 안에만 넘어가면 통과한다.
