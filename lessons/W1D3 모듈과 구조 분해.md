## 개념 (10분)

### 왜 파일을 나누나

W1D2 에서 `passRate` 를 `d2-objects-arrays.js` 로 **복사**해 왔다. 그러면

- `passRate` 를 고칠 때 복사본마다 다 고쳐야 한다. 하나라도 빠뜨리면 파일마다 결과가 달라진다.
- 같은 이름을 두 번 선언해도 에러 없이 뒤의 것이 덮어썼다.

**모듈**은 함수를 한 파일에 두고, 필요한 파일에서 **빌려 쓰는** 방법이다. 고칠 곳이 한 군데가 된다. W4 의 POM 도 같은 생각이다.

### 준비: 이 폴더는 모듈 방식으로 읽어라

`w1-js-basics/package.json` 파일을 만들고 한 줄만 쓴다.

```json
{ "type": "module" }
```

Node 에게 "이 폴더의 `.js` 파일은 `import`/`export` 방식으로 읽어라"라고 알려 주는 설정이다.

### 내보내기 `export` 와 가져오기 `import`

```js
// math.js — 내보내는 쪽
export function add(a, b) {
  return a + b;
}
export const double = (n) => n * 2;
const secret = 42;            // export 를 안 붙이면 이 파일 안에서만 쓴다
```

```js
// main.js — 가져오는 쪽
import { add, double } from './math.js';

console.log(add(1, 2));   // 3
console.log(double(5));   // 10
```

- `./` 는 "지금 파일과 같은 폴더", 경로 끝의 `.js` 까지 적는다.
- `{ }` 안에는 내보낸 **이름 그대로** 적는다.

Playwright 테스트 파일의 첫 줄이 바로 이 문법이다.

```js
import { test, expect } from '@playwright/test';
```

`@playwright/test` 라는 남이 만든 모듈에서 `test` 와 `expect` 를 빌려 오는 것이다. 경로가 `./` 로 시작하지 않으면 내 파일이 아니라 **설치한 패키지**라는 뜻이다(W2 에서 설치).

### 구조 분해: 객체에서 필요한 이름표만 꺼내기

```js
const tc = { id: 'TC-001', title: '로그인 성공', passed: true };

// 전에 배운 방식
const id = tc.id;
const passed = tc.passed;

// 구조 분해: 같은 일을 한 줄로
const { id, passed } = tc;
```

함수가 객체를 받을 때도 쓴다.

```js
const label = ({ id, passed }) => `${id}: ${passed}`;
label(tc);   // 'TC-001: true'
```

이제 W1D1 에서 남겨 둔 조각이 풀린다.

```js
test('로그인', async ({ page }) => { ... });
```

Playwright 는 테스트 함수를 부를 때 **여러 도구가 든 객체**를 넘겨준다. `({ page })` 는 그 객체에서 `page` 하나만 꺼내 쓰겠다는 뜻이다. (`async` 는 W1D4)

## 예측 퀴즈 (실행하기 전에 답을 적는다)

**Q1.** `main.js` 를 실행하면 세 줄이 어떤 **순서**로 출력될까?

```js
// utils.js
console.log('utils 로드됨');
export const rate = (p, t) => (p / t * 100).toFixed(1) + '%';
```

```js
// main.js
import { rate } from './utils.js';
console.log('main 시작');
console.log(rate(3, 5));
```

내 예측: 
utils 로드됨
main 시작
60.0%

**Q2.** 두 줄은 각각 무엇을 출력할까?

```js
const tc = { id: 'TC-003', title: '빈 비밀번호', passed: false };
const { id, title } = tc;
console.log(id, title);

const { priority } = tc;
console.log(priority);
```

내 예측: TC-003 빈 비밀번호
undefined

**Q3.** `package.json` 을 만든 뒤 W1D2 의 `node d2-objects-arrays.js` 를 다시 실행하면 어떻게 될까? (힌트: 이 파일에는 `function passRate` 가 두 번 있다)

내 예측: package.json 이 없을 때에는 직전에 선언된 함수가 각각 실행되었지만, package.json 을 만든 뒤에는 SyntaxError 가 발생해요. 어차피 export, import 한 행위가 없으니 괜찮을 거라고 생각했는데 "type": module 을 넣으니 Node가 더 엄격한 규칙으로 읽네요.

### 과제 2. 함수와 데이터를 각자의 파일로

| 파일 | 담을 것 |
|---|---|
| `qa-utils.js` | 맨 위에 `console.log('qa-utils 로드됨');` 한 줄, 그리고 `isAdmin`·`formatResult`·`passRate`(W1D2 의 `throw` 버전)를 `export` |
| `test-data.js` | W1D2 의 `results` 배열(5행)을 `export` |
| `d3-modules.js` | 위 두 파일에서 `import` 해서 아래 표의 출력을 만든다 |

`d3-modules.js` 의 목표 출력 (이름표를 붙인다)

| 할 일 | 목표 |
|---|---|
| ① 통과 개수 | `3` |
| ② 통과율 (`passRate` 사용) | `60.0%` |
| ③ 결과 줄 목록: `map` 과 구조 분해를 써서 `formatResult` 로 바꾸기 | `['TC-001: PASS', 'TC-002: PASS', 'TC-003: FAIL', 'TC-004: PASS', 'TC-005: FAIL']` |

힌트 ③: `results.map(({ id, passed }) => ...)`

함수는 `qa-utils.js`, 데이터는 `test-data.js`, 실행은 `d3-modules.js`. 이렇게 역할을 나누는 것이 W5 의 "데이터 분리"와 같은 생각이다.

### 과제 3. 고장 내기 (각각 예측 → 실행 → 원래대로 되돌리기)

1. `qa-utils.js` 에서 `formatResult` 앞의 `export` 를 지우면?
   - 내 예측: formatResult 함수를 d3 파일에서 사용하지 못할 것이다.
   - 실제 결과: SyntaxError: The requested module './qa-utils.js' does not provide an export named 'formatResult'
2. `import` 경로에서 `.js` 를 빼고 `'./qa-utils'` 로 쓰면?
   - 내 예측: SyntaxError 발생
   - 실제 결과: ERR_MODULE_NOT_FOUND 발생
3. (W1D2 에서 미룬 것) `d3-modules.js` 맨 아래에 두 줄을 넣으면 둘째 줄이 출력될까?
   ```js
   console.log(passRate(-1, 5));
   console.log('이 줄은 실행될까?');
   ```
   - 내 예측: throw Error 처리해놔서 실행을 막을 것 같다.
   - 실제 결과: 'Uncaught Error Error: 개수는 음수일 수 없습니다.' 로 나오고 둘째 줄이 출력되지 않는다.

## 설명하기 (10분)

1. `passRate` 를 `qa-utils.js` 한 곳에 두면, 나중에 계산 방식을 고칠 때 무엇이 좋아지나? -> 여러 파일에서 passRate 함수를 사용한다고 가정하면 qa-utils.js 에서만 수정해도 해당 함수를 사용하는 모든 파일에 반영될 것이다. 결론은 수정을 진행할 때 리소스를 적게 사용할 것이며, 이곳 저곳에 이름은 같고 출력은 다른 함수의 사용을 막을 수 있을 것 같다.
2. `import { test, expect } from '@playwright/test';` 를 한 조각씩 내 말로 읽는다. -> @playwright/test 파일에서 test와 expect 함수를 사용하고자 import 하였다. @playwright/test 는 ./로 시작하지 않으니까 내가 만든 파일이 아니라 설치한 패키지다.
3. `test('로그인', async ({ page }) => { ... });` 에서 `{ page }` 는 무엇인가? -> playwright 가 넘겨준 도구 객체에서 page만 구조 분해로 꺼내온 것이다.
4. Q3 에서 `d2` 파일이 왜 깨졌나? 깨진 것은 좋은 일인가 나쁜 일인가? -> package.json 이 없을 때에는 앞의 passRate가 아무런 Error 없이 덮어 씌워진 채로 실행되었고, package.json 이 있을때에는 실행전에 바로 Error 발생하여 터지도록 되었어요. Error 를 throw 처리한 것 처럼 이상한 값이 나올 바에는 확실히 Error 로 실행이 막히면 알아챌 수 있어서 좋은일 입니다.
