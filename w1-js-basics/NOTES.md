    - `throw`는 이상한 입력이 들어왔을 때 실행을 멈춰야 하는 곳에 쓴다.
    - `filter`는 배열에서 조건에 맞는 객체를 모두 골라 새 배열로 돌려준다. `find`는 조건에 맞는 첫 번째 객체 하나를 돌려준다.
    - 개수를 세려고 `count` 같은 함수를 찾았는데, `filter` 결과가 배열이라 `.length`를 붙이면 개수가 나온다.
    - `const`로 선언한 객체도 안의 값은 바꿀 수 있다. `const`가 막는 것은 변수에 다른 객체를 통째로 다시 대입하는 것이다.
- 🧱 막힌 곳 → 푼 방법:
    - `filter`·`find`에 화살표 함수를 넣어 한 번에 골라내는 게 감이 안 왔다 → 개념을 다시 읽고 적용해서 풀었다.
    - 다음에도 헷갈릴 것 같다. 반복해서 손에 익히는 게 가장 좋은 방법인 것 같다.

## W1D3 모듈과 구조 분해 (2026-11-10 · 소요 ?분)
- 이해도: 예측 △ · 고장 △ · 변형 △ · 설명 △
- ✅ 알게 된 것:
    - 배열과 객체를 서로 반대로 알고 있었다. 이번에 `results`는 배열(표 전체), `results[0]`은 객체(한 행)라는 걸 확실히 알게 됐다.
    - `import`하면 Node는 두 단계로 진행한다.
        - ① 읽기 단계: import된 파일들을 실행하지 않고 읽어서, 내가 적은 이름이 진짜 `export`돼 있는지 확인한다. 없으면 이 단계에서 `SyntaxError`로 멈추고 아무것도 실행되지 않는다.
        - ② 실행 단계: import된 파일들을 import 순서대로 한 번씩, 위에서부터 실행해서 `export`할 값을 만든다. 필요한 함수만 적어도 파일 전체가 실행된다. 그다음에 내 파일이 실행된다.
        - 이때 함수는 만들어지기만 하고, 함수 안쪽은 내가 불러야 실행된다.
    - 패키지는 늘 설치해서 썼기 때문에 `import`를 자연스럽게 썼었다. 내 파일끼리 `export`/`import` 하려면 `package.json`에 `"type": "module"`을 선언해야 한다. 이렇게 하면 Node가 더 엄격하게 읽어서, 같은 이름 함수를 두 번 선언하면 `SyntaxError`로 막는다.
    - 구조 분해로 객체에서 여러 값을 한 줄에 꺼낼 수 있다. `{ }` 안에는 key와 똑같은 이름을 적어야 하고, 다르게 쓰면(`{ idx }`) 에러 없이 `undefined`가 나온다.
    - 꺼내면서 이름만 바꾸려면 `:`를 쓴다(`const { id: loginId } = tc;`). 왼쪽은 찾을 key, 오른쪽은 내가 쓸 이름이다. key 자체를 바꾸려면 새 객체를 만들고, 행이 여러 개면 `map`으로 바꾼다.
    - 현업에서는 기대값과 실제값처럼 같은 이름이 두 군데서 올 때, API의 `user_id`를 `userId`로 맞출 때, 막연한 `id`에 뜻을 붙일 때 이름을 바꿔 쓴다.
    - 변수·함수 이름은 소문자로 시작한다(`loginId`). 대문자로 시작하는 이름(`LoginPage`)은 클래스용이다.
- 🧱 막힌 곳 → 푼 방법:
    - `console.log()` 안에 과제 답을 한 줄로 쓰려니 잘 안 됐다 → `passedCount` 변수를 먼저 만들어 값을 담으니 잘 풀렸다. 두 줄이 됐지만 다음 과제에서도 `passedCount`를 다시 쓸 수 있었다.
        - 한 줄에 한 단계만 생각하게 되고, 이름을 지으면서 값의 모양(숫자)이 정리되기 때문이다. 현업에서도 이렇게 짠다.
    - VS Code 자동완성이 `.js`를 빼고 경로를 적어 줘서 `ERR_MODULE_NOT_FOUND`가 났다 → 경로 끝에 `.js`를 붙였다. 에디터에 빨간 줄이 없어도 실행해 봐야 안다.
- ❓ 아직 모르겠는 것:
    - `import`로 가져온 건 `test`, `expect`인데 `page`는 어디서 온 객체인가?
        - 지금까지 이해한 것: `map`이 행을 넣어 주듯, `test`가 테스트를 실행할 때 브라우저 탭을 새로 만들어 `{ page }` 자리에 넣어 준다. W2D1에서 브라우저가 뜨는 걸 보며 다시 확인한다.
- 📌 미룬 것: W2D1에서 `typeof test`, `typeof expect` 출력해 보기, `(tools) =>`로 받으면 Playwright가 막는지 확인


## W1D4 async와 await (2026-11-11 · 소요 ?분)
- 이해도: 예측 △ · 고장 △ · 변형 ○ · 설명 △
- ✅ 알게 된 것:
    - 손으로 테스트할 때는 페이지가 열리고 버튼 동작이 끝나기를 자연스럽게 기다렸다. 코드는 그걸 기다려 주지 않고 바로 다음 줄로 넘어간다. 예전에 페이지나 버튼을 못 찾았다는 에러를 많이 받은 이유가 이것이다.
    - 그래서 오래 걸리는 일 앞에는 `await`를 붙여 끝날 때까지 기다리게 한다. `await`는 `async`가 붙은 함수 안(또는 모듈 파일 맨 바깥)에서만 쓸 수 있고, 아니면 `SyntaxError`가 난다.
    - Promise는 오래 걸리는 함수가 값 대신 먼저 주는 교환권이다. `await` 없이 받으면 `data`에 배열이 아니라 교환권(`Promise { <pending> }`)이 들어가서 `data.filter`가 없다는 `TypeError`가 난다.
    - `await`는 받은 값을 쓰든 안 쓰든 그 줄에서 멈춘다. 그리고 기다려서 받은 값(`data`)을 써야 의미가 있다.
- 🧱 막힌 곳 → 푼 방법:
    - 없음
- ❓ 아직 모르겠는 것:
    - 화살표(`=>`)가 아직 익숙하지 않다. 특히 `results.map(({ id }) => id)`처럼 메서드 안에 화살표 함수와 구조 분해가 같이 들어가면 읽기 어렵다.
    - 예전에 `await`를 코드 줄마다 붙였었다. 필요하다 싶은 줄마다 붙여도 되는지, 어떻게 해야 효율적인 코드가 되는지 아직 모르겠다.
- 📌 미룬 것:
    - 화살표 함수 펼쳐 쓰기 연습: `getId`를 함수 선언 → 화살표 → 구조 분해 세 가지로 써 보고 `results[0]`을 넣어 `'TC-001'`이 나오는지 확인
    - W1D2 수업 파일 과제 3의 "이유"와 "0/0 결정과 이유" 칸 채우기
